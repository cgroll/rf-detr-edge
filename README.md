# RF-DETR Edge

Pipeline for deploying an [RF-DETR](https://github.com/roboflow/rf-detr) segmentation model to edge devices. Exports a trained PyTorch checkpoint to ONNX, applies dynamic quantization (FP32 → uint8), and runs test inference to compare outputs.

This README also serves as the write-up of **how to quantize RF-DETR and run it on an edge device** — see [How-to & learnings](#how-to--learnings).

> **Known issue:** The Flutter implementation differs from the Python reference in normalization, score thresholding and EXIF handling. If on-device results are worse than in Python, start with [Pitfalls / open points](#6-pitfalls--open-points).

Related repos:
- [cgroll/cabel-cabinet](https://github.com/cgroll/cabel-cabinet) — training of the segmentation model (`RFDETRSegPreview`, cable cabinet switches)
- [cgroll/flutter_cable_cabinet_app](https://github.com/cgroll/flutter_cable_cabinet_app) — Flutter app running the quantized model on-device (`lib/services/segmentation_service.dart`)

## Pipeline

Managed with [DVC](https://dvc.org/). Run all stages with:

```bash
dvc repro
```

| Stage | Description | Output |
|---|---|---|
| `export_onnx` | Export PyTorch checkpoint to ONNX | `rfdetr_seg_fp32.onnx` (133 MB) |
| `quantize_onnx` | Dynamic quantization to uint8 | `rfdetr_seg_uint8.onnx` (42 MB) |
| `inference_fp32` | Run inference with full-precision model | `inference_output_fp32.jpg` |
| `inference_uint8` | Run inference with quantized model | `inference_output_uint8.jpg` |

## Data

All large files (model weights, test images, inference outputs) live in `assets/` and are **gitignored**. No DVC remote is configured — this is a bring-your-own-data setup. You need to supply:

- `assets/checkpoint_best_regular.pth` — trained RF-DETR segmentation checkpoint (input to the pipeline)
- `assets/test_img_000000020014596465.jpg` — test image used by the inference stages

The checkpoint originally used here came from a run `inst_seg_cable_v3` (dataset `./data/experiment_2/`, Roboflow COCO-segmentation export), trained like `inst_seg_training.py` in the `cabel-cabinet` repo. Any `RFDETRSegPreview` checkpoint works.

ONNX models and inference output images are generated by the pipeline and cached locally by DVC.

## How-to & learnings

### 1. Versions

The export is sensitive to versions. This combination worked (see `pyproject.toml` / `uv.lock`):

- Python 3.10, `torch>=2.4,<2.5`, `onnx>=1.17,<1.18`
- `rfdetr[onnxexport]>=1.3.0`, `onnxruntime>=1.23.2`, `onnxscript`

### 2. Export to ONNX (`export_onnx.py`)

```python
from rfdetr import RFDETRSegPreview
model = RFDETRSegPreview(pretrain_weights="checkpoint_best_regular.pth", resolution=432)
model.export(output_dir="assets", simplify=False)   # writes assets/inference_model.onnx
```

- Use the same model class as in training (`RFDETRSegPreview` for segmentation) and pass the input `resolution` explicitly — it fixes the ONNX input shape.
- `simplify=False`: export without ONNX simplification to preserve the mask output.

### 3. Quantize (`quantize_onnx.py`)

```python
from onnxruntime.quantization import quantize_dynamic, QuantType
quantize_dynamic("rfdetr_seg_fp32.onnx", "rfdetr_seg_uint8.onnx", weight_type=QuantType.QUInt8)
```

- **Dynamic** quantization: weights are stored as uint8, activations are quantized on the fly at runtime. No calibration dataset needed.
- Size 133 MB → 42 MB. Compare fp32 vs. uint8 visually with the `inference_*` stages.

### 4. Model interface (resolution 432)

| | Name | Shape | Content |
|---|---|---|---|
| Input | `input` | `[1, 3, 432, 432]` float32 | RGB, scaled to [0,1], then ImageNet-normalized (mean `0.485, 0.456, 0.406`, std `0.229, 0.224, 0.225`), NCHW |
| Output | `dets` | `[1, N, 4]` | boxes as `(cx, cy, w, h)`, normalized to [0,1] |
| Output | `labels` | `[1, N, num_classes]` | class logits |
| Output | masks | `[1, N, 108, 108]` | mask logits (resolution / 4) |

Postprocessing (`test_onnx_inference.py`): per query take max class score → threshold → `cxcywh` → `xyxy` scaled by original width/height → sigmoid on masks, resize to original size, threshold 0.5. No NMS needed (DETR-style set prediction).

### 5. Running on an edge device (Flutter)

Implemented in `flutter_cable_cabinet_app`, `lib/services/segmentation_service.dart`:

- Package `onnxruntime: ^1.4.1` (pub.dev); the uint8 ONNX file is bundled as Flutter asset `assets/rfdetr_seg_uint8.onnx` (gitignored there — copy it in from this pipeline).
- Load: `OrtEnv.instance.init()`, `rootBundle.load(...)`, `OrtSession.fromBuffer(bytes, OrtSessionOptions())`.
- Preprocess with package `image`: decode → `copyResize` to 432×432 → fill a `Float32List` in CHW order → `OrtValueTensor.createTensorWithDataList(data, [1,3,432,432])`.
- Run with `session.runAsync(OrtRunOptions(), {inputName: tensor})`; identify outputs by name/shape; release tensors and outputs afterwards.
- Masks are turned into polygons (`MaskUtils.maskToPolygon`) for drawing.

### 6. Pitfalls / open points

Differences between the Python reference and the Dart implementation as of Feb 2026 — check these first if on-device results look worse than in Python:

- **Normalization:** Python applies ImageNet mean/std; the Dart code only divides by 255.
- **Score threshold:** Python thresholds the raw `labels` values at 0.5 (no sigmoid); Dart thresholds the raw value at 0.3 and applies sigmoid only for the displayed confidence. Decide on one convention (sigmoid first, then threshold).
- **EXIF orientation:** Python corrects EXIF rotation before inference (important for phone photos); Dart does not.
- The per-pixel loop for preprocessing in Dart is simple but slow; a candidate for optimization.
